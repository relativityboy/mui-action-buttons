# Async action buttons for MUI

`AIconButton` gives a MUI button feedback for a promise: pending, success, or an
error that the user can dismiss. These examples simulate requests locally;
they do not call a backend.

## Start here

Install `@relativity/mui-action-buttons` alongside React 18.2 or 19, React DOM,
MUI 6, and Emotion 11. Import the stylesheet once in your application.
The icons in these examples come from the optional `@mui/icons-material` package.

<Source language="tsx" code={`import { AIconButton } from '@relativity/mui-action-buttons';
import '@relativity/mui-action-buttons/styles.css';
import SaveIcon from '@mui/icons-material/Save';

async function saveChanges(): Promise<void> {
  const response = await fetch('/api/settings', { method: 'POST' });
  if (!response.ok) throw new Error('Unable to save settings.');
}

<AIconButton onClick={saveChanges} endIcon={<SaveIcon />}>
  Save changes
</AIconButton>`} />

Open **Components → AIconButton → Playground** for editable controls. Choose a
delay and outcome, then click the button. The Actions panel records callback
invocations; the toolbar switches the real MUI theme between light and dark.

## What happens after a click

1. **Pending:** existing start/end icons spin, `aria-busy` is set, and further
   clicks are ignored. The button remains enabled while the request runs.
2. **Success:** the original icons return and the background turns green for
   two seconds. A new request clears the previous flash and gets its own timer.
3. **Failure:** existing icons become warning icons and the background turns
   red. The failure message is exposed through `title` and `aria-label`.
4. **Dismiss and retry:** the first click after failure only dismisses the
   error. The next click invokes the callback again.

The callback has the signature `() => Promise<void>` and receives no click
event. Resolve to indicate success; throw or reject to indicate failure.
For `fetch`, check `response.ok` yourself because HTTP failures do not reject
the promise automatically.

## Accessibility and current limitations

- Provide visible button text or an explicit `aria-label`. With rich children,
  set `aria-label` to preserve the action's name when an error occurs.
- A button without start/end icons has no visual spinner. It still reports
  `aria-busy` and shows the success/error background.
- Success currently changes the background and restores the original icon;
  it does not render a checkmark.
- Use `sx` for styling. The component currently replaces the inline `style` prop.
- The feedback CSS targets native `button` elements. Using `href` or an anchor
  root does not get that feedback styling, and navigation is not held until
  the async callback finishes.
- The Accessibility panel reports findings. Existing accessibility limitations
  are reported as warnings during story tests rather than silently suppressed.
